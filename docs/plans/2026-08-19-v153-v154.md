## Release A — v1.5.3

### A1 Remote transcription cost bound (Codex-revised)

Gap: `MAX_UPLOAD_BYTES` caps a single upload; nothing caps the run.

Facts (Codex-corrected): the real send loop is `_post_whisper`
(whisper.py:296, urlopen at :336); cloud retries are split across three
layers (adapter forces `max_attempts=1`; `_run_chunked` chunk retries at
transcription_adapters.py:122; provider fallback in
`TranscriptionPipeline.run`); chunks are ~1.5 MiB / ~3.28 min
(`DEFAULT_MAX_CHUNK_BYTES`), NOT 24 MiB.

Design:

- `RemoteCostLedger` (stdlib dataclass in whisper.py): cumulative uploaded
  bytes + attempt count. **Charged immediately before `urlopen` in
  `_post_whisper`**; bytes = `len(multipart_body)` (the actual wire upload).
  Every loop iteration charges — retries, failed sends included.
- One ledger per public transcription run: `TranscriptionRequest` gains
  `remote_ledger` (default_factory), passed by `CloudWhisperAdapter` through
  `transcribe_file` → `_post_whisper` (new keyword arg, default None = no
  bound, keeps unit-test call sites working). The legacy
  `whisper.transcribe_video` entry point creates and passes its own ledger,
  so both paths are covered.
- Bounds env-tunable with validated parsing (malformed → default, like
  `WATCH_YTDLP_STALE_DAYS`): `WATCH_REMOTE_MAX_UPLOAD_MB` (default 256, 0
  disables) and `WATCH_REMOTE_MAX_ATTEMPTS` (**default 171** so the byte
  bound dominates at current 1.5 MiB chunks; 0 disables). No cost-in-dollars
  claims anywhere (provider-dependent).
- Typed terminal signal `RemoteCostExceeded` raised by the ledger.
  `_run_chunked` catches it SPECIALLY (it must not be swallowed by the
  generic retry): stop the current chunk, **flush receipts in `finally`**
  (today flushing happens only after the loop, transcription_adapters.py:167
  — an early escape would lose pending receipts), preserve completed
  segments, and return `failure_code="remote_cost_limit_exceeded"` — never
  rewritten to `incomplete_chunks`/`transcript_unavailable`.
- `TranscriptionPipeline.run`: after a `remote_cost_limit_exceeded` attempt,
  skip all remaining REMOTE adapters (probe short-circuit on
  `ledger.exhausted`); later LOCAL adapters still run if configured.
- Diagnostics truth: `remote_transmission` becomes based on sends ATTEMPTED,
  not processed chunks (today a failed upload reports as no transmission).
- watch.py: render sanitized `--start/--end` guidance for BOTH partial and
  frames-only outcomes when the cost limit tripped (today only state +
  hard_cut warnings print). Exit 0.
- Exact-bound semantics: a send landing exactly on the cap is allowed;
  the next one is not.

Tests: captions/local never touch the ledger; zero remote sends after the
bound trips; exact-bound acceptance; focused-range fit; retry and
provider-fallback attempts each charge once (shared ledger across Groq →
OpenAI); pending-receipt flush on early escape; failed-upload
`remote_transmission` truth; custom adapter ordering (local after cloud
still runs); partial-report guidance rendering; disabled (0) semantics;
malformed env; legacy `transcribe_video` bound; final exit 0.

## Release B — v1.5.4 (all three Codex-revised; re-gate before build)

### B1 Whisper repetition-loop defense

Codex corrections adopted: chunks are ~3.3 min, so bisection is unjustified
— DROPPED. There is no existing invalid-segment retry path (`_run_chunked`
breaks on any nonempty output before validation); detection must live
INSIDE every attempt and ALSO on receipt reads (cached loops from old runs,
or from a `WATCH_LOOP_DETECT=0` run, must not resurface).

- Detector: pure function over a chunk's segments; normalization + sentence
  splitting defined in code; detects BOTH consecutive-identical-segment runs
  AND intra-segment repetition (one huge segment containing thousands of
  repeats). Empty/non-speech markers excluded.
- Calibration BEFORE thresholds are frozen: positive control synthesized
  from the documented 6,434x failure shape; negative fixtures for chant,
  chorus, call-and-response, meditation, applause/music markers, credits.
  Thresholds ship only when all fixtures pass both directions.
- Wiring: per-attempt validation inside `_run_chunked` (a looped attempt is
  a failed attempt → existing bounded retry → chunk fails); receipt reads
  validated with the same detector; `RECEIPT_SCHEMA` bumped (or cache reads
  keyed to detector policy) so pre-detector receipts revalidate; detected
  loops never stored.
- Escape hatch `WATCH_LOOP_DETECT=0` through normal config parsing +
  diagnostics; documented that disabling does not poison receipts (schema
  key includes policy).
- Tests: old-receipt revalidation, escape-hatch toggle, intra-segment case,
  absolute + word timestamps preserved, Windows, A1-ledger interaction
  (looped remote chunk retries still charge the ledger).

### B2 Original-language caption preference

Codex corrections adopted: unset `WATCH_LANGUAGE` resolves to `("en",)`,
not `("auto",)`; manual-over-ASR ordering in `download._subtitle_candidates`
is a frozen retrieval guard (test_retrieval_robustness.py:28) and MUST hold.

- Scope: the `-orig` request applies to the yt-dlp pattern list only —
  `.*-orig` variants (both base `en-orig` and regional forms) added, `en.*`
  wildcard dropped from the auto default (429 mitigation). Selection
  ordering: exact manual track first, same-language `-orig` next,
  translations last. An original may beat a TRANSLATION, never a
  same-language manual track.
- Structured provenance derived from `info.json` (not filenames): track
  code, language, manual/automatic, original/translated — recorded against
  the caption path actually CONSUMED, surviving watch.py's second
  acquisition (`dl` overwrite) so the report never describes a different
  track than the transcript used.
- Evidence-retrieval protection: before any default change that can select
  a non-English transcript for an English question, run the evidence-mode
  benchmark against 83da59f; if retrieval degrades, gate the preference to
  explicit `WATCH_LANGUAGE=auto` only.
- Tests: deterministic fixtures mandatory (pattern ordering, candidate
  ordering incl. manual-first freeze, provenance-vs-consumed-path under
  double acquisition); live non-English/English checks opt-in, non-gating.

### B3 Timestamps in main-pass frame filenames

Codex corrections adopted:

- ONE post-selection helper, invoked after dedup AND after even-sampling,
  on every exit: scene, uniform, keyframe (incl. cleanup/discovery at
  frames.py:939/:967), fallback, no-dedup, and the standalone frames CLI.
  watch.py consumes returned dict paths — update each dict path only AFTER
  its rename succeeds.
- Naming: `frame_0007_t04m12s.jpg`, hours `t1h04m12s`; nearest-second via
  the same rule as `format_time`; colon-free (Windows); collision = never
  overwrite (check destination + catch all rename `OSError`s, keep original
  path on failure — fail-open).
- Control conformance: `tools/control_conformance.py` compares names —
  canonicalize or explicitly declare the filename-only delta while keeping
  timestamp/dimension/byte/hash comparisons strict.
- Tests: every engine/fallback exit, partial rename failure, stale
  collision, Windows-safe names, glob discovery (frames.py:310/:340/:373/
  :415/:939/:967), exact on-disk == report path equality, hour rollover.
