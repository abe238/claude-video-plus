# v3 dedup blind-spot — measurement gate (2026-08-26)

Go/no-go measurement before building a v3 frame engine, per the fork-watch
absorption of `HUANGCHIHHUNGLeo/claude-real-video`'s v0.7.4 "settled-local"
finding. Question: does our **default engine (v2)** drop distinct on-screen
states when the change between them is small (caption swap, a new bullet), and
is a fix cheap enough in pure stdlib (no Pillow at runtime)?

## Method

Synthetic fixtures with a KNOWN number of states (6 each, one per 5s window),
generated by `measure.py`; the real `watch.py --detail balanced` extraction is
run on each, and a state's window counts as "captured" if ≥1 kept frame lands in
it. A **positive control** (6 full-frame hard cuts) validates the probe — if the
control ever drops below 6/6, the measurement is untrustworthy.

Fixtures: `caption_swap` (static bg + fixed title, only a bottom caption line
changes), `ui_bullets` (a slide gains one bullet per state), `positive_control`
(6 distinct full-frame color slides).

## Result 1 — the blind spot is real and severe (real pipeline, ground truth)

| Fixture | states present | states captured (v2 default) | frames kept |
|---|---|---|---|
| positive_control | 6 | **6** ✓ (probe valid) | 6 |
| caption_swap | 6 | **1** (missed 5) | 1 |
| ui_bullets | 6 | **2** (missed 4) | 2 |

`--no-dedup` on `caption_swap` recovers **6/6** states (30 frames) — proving the
**dedup decision**, not candidate supply, is the killer (uniform sampling already
provides 30 frames; v2's comparator collapses 29 of them).

## Result 2 — root cause quantified

Signal between two adjacent caption states, by signature resolution:

| signature | global % cells changed | worst local block changed |
|---|---|---|
| 16px (v2 default) | **0.0%** | 0% |
| 32px | 0.1% | 6% |
| 64px | 0.4% | 8% |
| 128px | 0.6% | 14% |

v2 keeps a frame only when **global** change > 2%. A caption is <1% of frame
area, so it is **0.0–0.6% globally at every resolution** — invisible to a global
threshold no matter how large the signature (confirmed: `cost_spike.py` keeps
1/6 at 16/32/64px). The change only shows up **locally** (6–14% of a single
block at ≥32px). So the fix is a **local-region detector**, not a bigger global
signature.

## Result 3 — cost is sane in pure stdlib

One extra ffmpeg pass emits NxN grayscale thumbnails (C-speed, the mechanism v2
already uses at 16px); the Python scoring over a 30s clip's 300 thumbnails:
~1.5 ms (16px) to ~110 ms (64px block scoring). No Pillow needed. Cost is not a
barrier.

## Result 4 — the detector is non-trivial (not a threshold tweak)

Both quick spikes FAILED to recover the states: a bigger global signature
(`cost_spike.py`, 1/6 at 64px) and a naive high-threshold block detector
(`cost_spike2.py`, 50%-block keep → 1/6, because the real local signal is only
6–14%). A working v3 detector must (a) use a ≥32–64px signature, (b) score
**local blocks** with a threshold in the measured ~5–15% range, and (c) guard
against grain/noise and camera jitter on real footage (crv's shift-tolerance +
"settled, not still-moving" gate + cooldown) so it does not over-keep. This is
crv's v0.7.3→v0.7.4 effort, tuned against this corpus AND real footage.

## Verdict: **GO on v3, justified by receipts**

- The miss is real and large (1/6, 2/6 vs a valid 6/6 control), on the default
  engine, with ground truth. Not a corner case: caption/slide/screencast content
  is core input.
- The cost is sane in stdlib.
- BUT it is a genuine detector-design effort, not a threshold change. Build it as
  a new **opt-in v3 engine** (never silently redefine the benchmarked v2), tuned
  on this corpus + real footage, fail-open, and gated vs the frozen control
  `83da59f`. Flip the default only after it recovers these states AND does not
  over-keep on real grainy footage (a jfk-rice-style clip) — the same staged
  bar v2 cleared.

## Reproduce

```
python3 docs/benchmarks/2026-08-26-v3-blindspot/measure.py       # states captured (real pipeline)
python3 docs/benchmarks/2026-08-26-v3-blindspot/cost_spike.py    # bigger global signature (fails)
python3 docs/benchmarks/2026-08-26-v3-blindspot/cost_spike2.py   # naive block detector (fails)
```
